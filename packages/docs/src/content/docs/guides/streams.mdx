DynamoDB Streams deliver a time-ordered sequence of item-level changes. effect-dynamodb provides utilities for decoding stream records into typed domain objects.

## Understanding the Problem

DynamoDB Stream records contain items in DynamoDB's native `AttributeValue` format:

```json
{
  "pk": { "S": "$myapp#v1#employee#employeeid_emp-alice" },
  "sk": { "S": "$myapp#v1#employee" },
  "__edd_e__": { "S": "Employee" },
  "email": { "S": "alice@acme.com" },
  "version": { "N": "1" }
}
```

Manually decoding this into your domain types is error-prone. effect-dynamodb provides `Entity.decodeMarshalledItem` for AttributeValue input and `Entity.itemSchema` for already-unmarshalled input.

Images can also carry two other hidden attributes: `__edd_i__`, the incarnation token on items of a versioned entity, and `__edd_d__`, a string set naming unique fields that hold only a decoding default. Decoded models never include them. `Entity.decodeMarshalledItem` refuses, with a `ValidationError`, an image of a versioned entity that has `__edd_i__` but no version, because its version was removed outside the library.

## Setup

The examples on this page use these models and entities:

```typescript region="models" example="guide-streams.ts"
class Employee extends Schema.Class<Employee>("Employee")({
  employeeId: Schema.String,
  email: Schema.String,
  displayName: Schema.NonEmptyString,
  department: Schema.String,
}) {}

const EmployeeModel = DynamoModel.configure(Employee, {
  email: { immutable: true },
})

class Task extends Schema.Class<Task>("Task")({
  taskId: Schema.String,
  employeeId: Schema.String,
  title: Schema.NonEmptyString,
  status: Schema.String,
}) {}
```

```typescript region="entities" example="guide-streams.ts"
const AppSchema = DynamoSchema.make({ name: "myapp", version: 1 })

const EmployeeEntity = Entity.make({
  model: EmployeeModel,
  entityType: "Employee",
  primaryKey: {
    pk: { field: "pk", composite: ["employeeId"] },
    sk: { field: "sk", composite: [] },
  },
  indexes: {
    byDepartment: {
      name: "gsi1",
      pk: { field: "gsi1pk", composite: ["department"] },
      sk: { field: "gsi1sk", composite: ["displayName"] },
    },
  },
  timestamps: true,
  versioned: true,
})

const TaskEntity = Entity.make({
  model: Task,
  entityType: "Task",
  primaryKey: {
    pk: { field: "pk", composite: ["taskId"] },
    sk: { field: "sk", composite: [] },
  },
  indexes: {
    byEmployee: {
      name: "gsi1",
      pk: { field: "gsi1pk", composite: ["employeeId"] },
      sk: { field: "gsi1sk", composite: ["status"] },
    },
  },
  timestamps: true,
})

const MainTable = Table.make({
  schema: AppSchema,
  entities: { EmployeeEntity, TaskEntity },
})
```

## Decoding from AttributeValue Format

For Lambda functions consuming DynamoDB Stream events directly, use `Entity.decodeMarshalledItem`. It unmarshalls the `AttributeValue` map and decodes it as a table read does, in a single step: `field:` renames are reversed, [sparse maps](/effect-dynamodb/guides/sparse-maps/) are rebuilt, and [packed fields](/effect-dynamodb/guides/packed-storage/) are decoded by their stored form. It returns an `Effect` that fails with `ValidationError` on schema mismatch, or when a compressed value's codec isn't registered (the error's `cause` is then a `CompressorNotRegistered`). [Offloaded fields](#offloaded-fields-in-stream-records) come back as lazy handles:

```typescript region="decode-marshalled" example="guide-streams.ts"
const handleEmployeeStream = (event: DynamoDBStreamEvent) =>
  Effect.gen(function* () {
    for (const record of event.Records) {
      if (record.dynamodb?.NewImage) {
        const employee = yield* Entity.decodeMarshalledItem(
          EmployeeEntity,
          record.dynamodb.NewImage,
        )
        yield* Console.log(`Updated: ${(employee as Employee).displayName}`)
      }
    }
  })
```

## Decoding from Unmarshalled Format

If you've already unmarshalled the item (e.g., using `Marshaller.fromAttributeMap` or `@aws-sdk/util-dynamodb`), use `Entity.itemSchema` to get a Schema codec for direct decoding. It's a pure schema: it doesn't map `field:` renamed attributes back to their domain names, rebuild sparse maps, decode packed fields or resolve offloaded ones. For an entity that uses any of those, pass the unmarshalled item to `Entity.decodeMarshalledItem` instead, which accepts both forms:

```typescript region="decode-unmarshalled" example="guide-streams.ts"
const employeeFromItem = Entity.itemSchema(EmployeeEntity)

const decodeUnmarshalledEmployee = (marshalledImage: Record<string, AttributeValue>) => {
  const unmarshalled = Marshaller.fromAttributeMap(marshalledImage)
  return Schema.decodeUnknownEffect(employeeFromItem)(unmarshalled)
}
```

## Typing the Marshalled Shape

The `Entity.Marshalled<E>` type represents the shape of a DynamoDB item in `AttributeValue` format:

```typescript region="marshalled-type" example="guide-streams.ts"
type EmployeeMarshalled = Entity.Marshalled<typeof EmployeeEntity>
// {
//   readonly [x: string]: {
//     readonly S?: string
//     readonly N?: string
//     readonly BOOL?: boolean
//     readonly NULL?: boolean
//     readonly L?: ReadonlyArray<unknown>
//     readonly M?: Record<string, unknown>
//     readonly B?: Uint8Array
//   }
// }
```

## Processing Multiple Entity Types

When processing streams from a single-table design, use `__edd_e__` to discriminate entity types and decode each with `Entity.decodeMarshalledItem`:

```typescript region="multi-entity" example="guide-streams.ts"
const handleStreamEvent = (event: DynamoDBStreamEvent) =>
  Effect.gen(function* () {
    for (const record of event.Records) {
      const image = record.dynamodb?.NewImage
      if (!image) continue

      const entityType = image["__edd_e__"]?.S
      switch (entityType) {
        case "Employee": {
          const emp = yield* Entity.decodeMarshalledItem(EmployeeEntity, image)
          yield* handleEmployeeChange(emp as Entity.Record<typeof EmployeeEntity>)
          break
        }
        case "Task": {
          const task = yield* Entity.decodeMarshalledItem(TaskEntity, image)
          yield* handleTaskChange(task as Entity.Record<typeof TaskEntity>)
          break
        }
      }
    }
  })

const handleEmployeeChange = (emp: Entity.Record<typeof EmployeeEntity>) =>
  Console.log(`Employee changed: ${emp.displayName} (${emp.email})`)

const handleTaskChange = (task: Entity.Record<typeof TaskEntity>) =>
  Console.log(`Task changed: ${task.title} (${task.status})`)
```

## Binary Values and Packed Storage

Lambda triggers and EventBridge Pipes deliver stream records as DynamoDB JSON with `B` and `BS` values as **base64 text**, and `@aws-sdk/util-dynamodb`'s `unmarshall` leaves them as text. `Entity.decodeMarshalledItem` decodes them at any depth, so a [packed field](/effect-dynamodb/guides/packed-storage/) compressed to `B` decodes the same from a stream record as from a table read.

For an EventStore stream, `stream.decodeStreamImage(image)` returns exactly the `StreamEvent` the read paths return, or `Option.none()` for an image that isn't one of the stream's events:

```typescript region="stream-image" example="guide-packed-storage.ts"
// One handler for a table's NewImage records. decodeStreamImage returns
// Option.none() for anything that is not one of the stream's events.
const decodeImage = (image: EventStore.StreamImage) =>
  Effect.gen(function* () {
    const event = yield* Ledger.decodeStreamImage(image)
    if (Option.isSome(event)) {
      // Exactly the StreamEvent Ledger.read returns
      return `ledger ${event.value.version}: ${event.value.data._tag}`
    }
    const order = (yield* Entity.decodeMarshalledItem(Orders, image)) as Order
    return `order ${order.orderId}: ${order.lines.length} line(s)`
  })
```

Compressors come from a `Compression` service in context (for example `Compression.layer([...])` merged into the application layer), as for table reads. See [DynamoDB Streams images](/effect-dynamodb/guides/packed-storage/#dynamodb-streams-images) in the Packed Storage guide.

## Offloaded Fields in Stream Records

A field [offloaded to a blob store](/effect-dynamodb/guides/blob-offload/) is stored in the item as a pointer. Stream decoding is **lazy** by default, so a consumer pays a store `GET` only for the values it reads:

```typescript region="offloaded-entity" example="guide-streams.ts"
class Contract extends Schema.Class<Contract>("Contract")({
  contractId: Schema.String,
  terms: Schema.Struct({ clauses: Schema.Array(Schema.String) }),
  signed: Schema.Uint8Array,
}) {}

const ContractEntity = Entity.make({
  model: DynamoModel.configure(Contract, {
    // In the blob store at or over 32 KiB stored, inline below
    terms: { storedAs: DynamoModel.Packed({ format: "json", external: { threshold: 32_768 } }) },
    // Always in the blob store
    signed: { storedAs: DynamoModel.External({ contentType: "application/pdf" }) },
  }),
  entityType: "Contract",
  primaryKey: {
    pk: { field: "pk", composite: ["contractId"] },
    sk: { field: "sk", composite: [] },
  },
})
```

```typescript region="decode-lazy" example="guide-streams.ts"
const handleContractImage = (image: Record<string, AttributeValue>) =>
  Effect.gen(function* () {
    // Typed for an entity that offloads: its offloaded fields come back lazy
    const contract = yield* Entity.decodeMarshalledItem(ContractEntity, image)
    const terms = yield* contract.terms.read() // OffloadedValue: one GET, on read()
    const header = yield* contract.signed.read({ range: { offset: 0, length: 4 } }) // BlobHandle

    // { offloaded: "eager" } resolves both kinds while decoding
    const eager = yield* Entity.decodeMarshalledItem(ContractEntity, image, {
      offloaded: "eager",
    })
    const pdf: Uint8Array = eager.signed
    return { clauses: terms.clauses.length, header, bytes: pdf.length }
  })
```

- **`decodeMarshalledItem`** is typed for an entity that offloads: its record, with each offloaded field an `OffloadedValue` (overflow, `read()`) or a `BlobHandle` (binary, `read`, `stream`, `presignedUrl`), inline values included. For an entity that offloads nothing it still returns `unknown`. `{ offloaded: "eager" }` (or `{ overflow, binary }`) resolves while decoding, and a store failure is then a `BlobStoreError`.
- **The store** comes from the `BlobStore` in context where the decode runs (a handle captures it, so its `read()` needs nothing). Without one, an eager decode or a handle's `read()` fails with `BlobStoreError { reason: "NotProvided" }`.
- **Adding `external` changes what lazy decoders return** for that field, even for values still inline. Code that casts an `unknown` result only sees the change at run time: decode through the typed overload.

### Change detection

`Entity.decodeStreamRecord` decodes both images of a record and classifies what the change did to each offloaded field, from the two pointers alone, with no store I/O:

```typescript region="decode-stream-record" example="guide-streams.ts"
// A record of a NEW_AND_OLD_IMAGES stream: both images, and what the change
// did to each offloaded field, read from the two pointers alone
const handleContractRecord = (record: Entity.StreamRecordLike) =>
  Effect.gen(function* () {
    const change = yield* Entity.decodeStreamRecord(ContractEntity, record)
    if (Option.isNone(change)) return "not a contract"
    const { offloaded, newItem } = change.value
    // "rewritten" is probably the same content: a consumer that must never
    // miss a change treats it as "changed"
    const signed = offloaded.signed
    if (signed === "unchanged" || Option.isNone(newItem)) return "signature unchanged"
    const bytes = yield* newItem.value.signed.read() // fetched only here
    return `signature ${signed}: ${bytes.length} bytes to re-index`
  })
```

It returns `Option.none()` for a record of another entity type, and otherwise an `EntityChange`: `eventName`, `oldItem` and `newItem` (each an `Option`, decoded in the call's read modes, lazy by default) and `offloaded`, one of these per offloaded field present in either image:

| Value | Meaning |
|---|---|
| `unchanged` | the same object version, or inline values with the same content |
| `rewritten` | another version (or stored form) with the same checksum algorithm, checksum and content size: **probably** the same content |
| `changed` | different content |
| `added` / `removed` | only in the new / old image |

`rewritten` is probable, not proven: a CRC can be matched by crafted content, so a consumer that must never miss a change (an indexer, a malware scanner) treats it as `changed`, or compares the content. The stream must use `NEW_AND_OLD_IMAGES`: a record of another view type, or one missing an image its event needs, fails with a `ValidationError` naming `[EDD-9119]`. `decodeStreamRecord` accepts the SDK's records, Lambda's and EventBridge Pipes' (`B` as base64 text), and Kinesis Data Streams' (`Entity.StreamRecordLike` is structural).

For a consumer that decodes no entity, `Offload.compareStored(old, new, kind)` is the same classification over two raw attribute values, and `StorageEncoding.pointer` reads the pointer a stored value holds:

```typescript region="compare-stored" example="guide-streams.ts"
// Without an entity: classify one attribute of the two images, and read a pointer
const compareSigned = (record: Entity.StreamRecordLike) =>
  Effect.gen(function* () {
    const oldImage = record.dynamodb?.OldImage as Record<string, AttributeValue> | undefined
    const newImage = record.dynamodb?.NewImage as Record<string, AttributeValue> | undefined
    const change = yield* Offload.compareStored(oldImage?.signed, newImage?.signed, "binary")
    const pointer =
      newImage?.signed === undefined ? Option.none() : StorageEncoding.pointer(newImage.signed)
    // pointer.value → { kind: "bytes", ref: { key, version }, objectSize, contentType, … }
    return { change, pointer }
  })
```

### A lagging consumer can read `NotFound`

A handle decoded from an old record names a version that may since have been superseded and freed by the [reaper](/effect-dynamodb/guides/blob-offload/#the-reaper), once its grace has passed. The newer record carries the newer pointer, so catch `BlobStoreError` with `reason: "NotFound"` and skip the field rather than failing the batch, which would wedge the shard. Choose a reaper grace at least as long as the slowest consumer's tolerated lag.
