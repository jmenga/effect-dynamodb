Module-by-module reference for all public exports of `effect-dynamodb`.

## DynamoModel

Provides annotations, date schemas, storage modifiers, and model configuration for effect-dynamodb.

```typescript
import { DynamoModel } from "effect-dynamodb"
```

### Annotations

| Export | Type | Description |
|--------|------|-------------|
| `Hidden` | `<S>(schema: S) => S` | Marks a field as hidden from `asModel`/`asRecord` decode. Still stored in DynamoDB, visible in `asItem`/`asNative` |
| `isHidden` | `(schema: Schema.Top) => boolean` | Check if a schema field has the `Hidden` annotation |
| `identifier` | `<S>(schema: S) => S` | Marks the primary business identifier on a model. Exactly one per entity. Required for entities referenced via `ref` |
| `isIdentifier` | `(schema: Schema.Top) => boolean` | Check if a schema field has the `identifier` annotation |
| `getIdentifierField` | `(model: Schema.Top) => { name, schema } \| undefined` | Find the identifier field in a model's `.fields` |
| `ref` | `<S>(schema: S) => S` | Marks a field as a denormalized reference to another entity. Transforms types in Entity (Input: ID, Record: full object, Update: optional ID) |
| `isRef` | `(schema: Schema.Top) => boolean` | Check if a schema field has the `ref` annotation |
| `getRefAnnotation` | `(schema: Schema.Top) => RefAnnotation \| undefined` | Get the full ref annotation metadata |

### Date Schemas

All date schemas carry a `DynamoEncoding` annotation that controls how the field is stored in DynamoDB.

| Export | Wire Type | Domain Type | DynamoDB Storage |
|--------|-----------|-------------|------------------|
| `DateString` | ISO 8601 string | `DateTime.Utc` | String (`S`) |
| `DateEpochMs` | epoch milliseconds | `DateTime.Utc` | Number (`N`) |
| `DateEpochSeconds` | epoch seconds | `DateTime.Utc` | Number (`N`) |
| `DateEpoch(opts)` | auto-detect ms/seconds | `DateTime.Utc` | configurable |
| `DateTimeZoned` | ISO+offset+zone string | `DateTime.Zoned` | String (`S`) |
| `UnsafeDateString` | ISO 8601 string | native `Date` | String (`S`) |
| `UnsafeDateEpochMs` | epoch milliseconds | native `Date` | Number (`N`) |
| `UnsafeDateEpochSeconds` | epoch seconds | native `Date` | Number (`N`) |
| `TTL` | epoch seconds | `DateTime.Utc` | Number (`N`) — alias for `DateEpochSeconds` |

### Storage Modifier

| Export | Type | Description |
|--------|------|-------------|
| `storedAs` | `<A>(storageSchema: Schema<A>) => (fieldSchema: Schema<A>) => Schema<A>` | Override DynamoDB storage format. Type-safe: domain types must match |

### Model Configuration

| Export | Type | Description |
|--------|------|-------------|
| `configure` | `(model, attributes) => ConfiguredModel<M>` | Wrap a model with per-field DynamoDB overrides (field renaming, storage encoding, immutable) |
| `isConfiguredModel` | `(value) => boolean` | Check if a value is a `ConfiguredModel` |

### Storage Layouts

Values for a field's `storedAs` in `configure` that change how a structured field is laid out on the item.

| Export | Type | Description |
|--------|------|-------------|
| `SparseMap` | `(options?: { prefix? }) => SparseMapConfig` | Store a `Schema.Record` as one top-level attribute per entry — see [Sparse Maps](/effect-dynamodb/guides/sparse-maps/) |
| `Packed` | `(options: { format: "json", compression?: { codec: "gzip" \| "brotli" \| "zstd", threshold? } }) => PackedConfig` | Store an object- or array-shaped field (or EventStore `data` / snapshot `state`) as one JSON string, compressed to binary at or above `threshold` (default 1024 bytes) when smaller. Keep the default: compressing small values (`threshold: 0`) saves read units but makes reads slower. Throws `[EDD-9071]` on invalid options. See [Packed Storage](/effect-dynamodb/guides/packed-storage/) |
| `isPackedConfig` | `(value) => value is PackedConfig` | Check if a value is a `Packed` config |
| `getPackedFields` | `(model) => Record<string, PackedConfig>` | Domain field name → config, for every field configured `storedAs: Packed(...)` |

### Encoding Utilities

| Export | Type | Description |
|--------|------|-------------|
| `DynamoEncodingKey` | `symbol` | Annotation key for reading DynamoEncoding from schema AST |
| `getEncoding` | `(schema) => DynamoEncoding \| undefined` | Read the DynamoEncoding annotation from a schema |

### Types

| Type | Description |
|------|-------------|
| `DynamoEncoding` | `{ storage: "string" \| "epochMs" \| "epochSeconds", domain: "DateTime.Utc" \| "DateTime.Zoned" \| "Date" }` |
| `ConfiguredModel<M>` | Wrapper carrying original model + per-field attribute overrides |
| `RefAnnotation` | `{ _tag: "Ref", refSchemaId?: string }` — annotation metadata for ref fields |

### Usage

```typescript
// Annotations
class Employee extends Schema.Class<Employee>("Employee")({
  employeeId: Schema.String,
  createdBy: Schema.String,
  internalId: Schema.String.pipe(DynamoModel.Hidden),
}) {}

// configure — immutable fields + field overrides
const EmployeeModel = DynamoModel.configure(Employee, {
  createdBy: { immutable: true },
})

// Date schemas
class Event extends Schema.Class<Event>("Event")({
  eventId: Schema.String,
  startedAt: DynamoModel.DateString,               // ISO string ↔ DateTime.Utc
  expiresAt: DynamoModel.DateEpochSeconds,          // epoch seconds (for TTL)
  scheduledAt: DynamoModel.DateTimeZoned,            // with timezone
}) {}

// storedAs — override storage format on a SELF schema (not a transform).
// `Schema.DateTimeUtc` is the self schema; the annotation drives storage.
class Order extends Schema.Class<Order>("Order")({
  orderId: Schema.String,
  // Domain: DateTime.Utc, stored as epoch seconds (e.g. for DynamoDB TTL).
  // Applying `storedAs` to a transform schema (e.g. DateString or
  // DateTimeUtcFromString) is rejected at Entity.make() time.
  expiresAt: Schema.DateTimeUtc.pipe(DynamoModel.storedAs(DynamoModel.DateEpochSeconds)),
}) {}

// configure — field renaming + storage overrides (self-schema only for storedAs)
const OrderModel = DynamoModel.configure(Order, {
  expiresAt: { field: "ttl", storedAs: DynamoModel.DateEpochSeconds },
})

// identifier — marks primary business ID for ref resolution
class Team extends Schema.Class<Team>("Team")({
  id: Schema.String.pipe(DynamoModel.identifier),
  name: Schema.String,
}) {}

// ref — denormalized reference to another entity
class Selection extends Schema.Class<Selection>("Selection")({
  team: Team.pipe(DynamoModel.ref),     // Input: teamId, Record: Team
  player: Player.pipe(DynamoModel.ref), // Input: playerId, Record: Player
}) {}
```

## DynamoSchema

```typescript
import { DynamoSchema } from "effect-dynamodb"
```

| Export | Type | Description |
|--------|------|-------------|

| `composeCollectionKey` | `(schema, collection, composites) => string` | Compose collection PK |
| `composeClusteredSortKey` | `(schema, collection, entity, composites) => string` | Compose clustered SK |

## Table

Minimal table definition with Layer-based name injection.

```typescript
import { Table } from "effect-dynamodb"
```

| Export | Type | Description |
|--------|------|-------------|
| `make` | `(config: { schema, entities?, aggregates? }) => Table` | Create a table definition with entities and aggregates |
| `definition` | `(table) => TableDefinition` | Derive `CreateTableCommandInput` fields from entity index declarations |

Both `make` and `definition` check the members against each other. Every member declaring one physical secondary index (an entity index, an auto-generated `_cascade_<field>` index, an aggregate's collection or list index) must agree on its key attributes and on whether it is a GSI or an LSI, and every entity must declare the same primary-key fields. A disagreement throws `[EDD-9069]`, naming both declarers. Tables deployed with CDK or Terraform get the check from `make` alone.

### Types

| Type | Description |
|------|-------------|
| `Table` | Interface with `schema`, `entities`, `aggregates`, `layer()`, `layerConfig()`, and `Tag` for DI |
| `TableConfig` | `{ name: string }` — runtime table configuration |
| `TableDefinition` | `{ KeySchema, AttributeDefinitions, GlobalSecondaryIndexes? }` |

### Usage

```typescript
const MainTable = Table.make({ schema: AppSchema, entities: { UserEntity, TaskEntity } })

// Runtime name injection via Layer
MainTable.layer({ name: "MyTable" })

// Typed client auto-derives table schema for creation
const db = yield* DynamoClient.make({
  entities: { UserEntity, TaskEntity },
  tables: { MainTable },
})
yield* db.tables.MainTable.create()
```

See [Modeling](/effect-dynamodb/guides/modeling/) for details.

## Entity

The core module — binds models to tables, provides CRUD operations, query accessors, lifecycle management, and 7 derived types. This is the largest module.

```typescript
import { Entity } from "effect-dynamodb"
```

### Construction

| Export | Type | Description |
|--------|------|-------------|
| `make` | `(config) => Entity` | Create an entity with model, table, indexes, and optional system fields |

**`make` config:**

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `model` | `Schema.Class \| Schema.Struct \| ConfiguredModel` | Yes | Domain model schema (or configured model with field overrides) |
| `entityType` | `string` | Yes | Discriminator stored as `__edd_e__` |
| `primaryKey` | `{ pk: KeyDef, sk: KeyDef, casing? }` | Yes | Primary key composition rules. Optional `casing` overrides the schema's for the primary key |
| `indexes` | `Record<string, GsiIndexDef>` | No | GSI index definitions with `name`, `pk`, `sk`, optional `collection`, `type`, `casing` (overrides the schema's for that index — collection members must agree, `EDD-9055`) and `indexPolicy` |
| `timestamps` | `boolean \| { created?, updated? }` | No | Auto-managed `createdAt`/`updatedAt`. Each slot takes a field name, a `DynamoModel` date schema (storage only), or `{ field?, schema? }`. A `schema` without a `DynamoEncoding` annotation throws `EDD-9044` at make() time |
| `versioned` | `boolean \| { retain?, field?, ttl? }` | No | Auto-increment version with optional snapshot retention |
| `softDelete` | `boolean \| { ttl?, preserveUnique? }` | No | Soft delete with optional TTL |
| `unique` | `Record<string, string[]>` | No | Unique constraint definitions |
| `refs` | `Record<string, Entity>` | No | Map ref field names to their source entities for ref hydration |

### Operations

These are methods on the entity definition returned by `Entity.make()`. They return **operation descriptors** used by `Transaction`, `Batch`, and advanced pipeable workflows. For day-to-day CRUD, use `DynamoClient.make(table)` to get a typed client with executable methods (see below).

| Operation | Signature | Description |
|-----------|-----------|-------------|
| `entity.put(input)` | `EntityPut` | Insert or overwrite an item (descriptor). On a versioned or unique-constrained entity it reads the item first: a put over an existing item continues its version, incarnation and `createdAt`, snapshots it (retain) and rotates changed sentinels, releasing only those it owns. A concurrent write in between is retried (last writer wins); a race lost on every attempt fails with `OptimisticLockError` / `ConcurrentModification`. A deleted retain item created again continues after its retained version history |
| `entity.create(input)` | `EntityPut` | Insert only — fails with `ConditionalCheckFailed` if exists (descriptor). Never reads the item; a `retain` entity runs one `Limit 1` query to continue after any version history retained at the key (with primary sort key composites, plus a keys-only `Limit 1` query for history an earlier release wrote) |
| `entity.upsert(input)` | `EntityPut` | Create or update the supplied fields — uses `if_not_exists()` for immutable fields, createdAt, version (descriptor). On an entity with unique constraints or `retain` (or an input omitting a defaulted index composite) it reads the item once: creates a missing item with its sentinels and snapshot, or updates an existing one, rotating changed sentinels and snapshotting it. Validates the whole input either way |
| `entity.get(key)` | `EntityGet` | Get a single item by primary key (descriptor) |
| `entity.update(key)` | `EntityUpdate` | Start an update operation (compose with `set`, `add`, etc.) (descriptor). On a missing item it fails with `ItemNotFound` and writes nothing. The exception is a plain `.set()` of a complete item (every required field and primary-key composite, with no other operations, `expectedVersion`, `.condition()`, cascade, `withVector` or old-image `returnValues`), which the library creates through `create`, exactly as `put` would write it |
| `entity.patch(key)` | `EntityUpdate` | Update with `attribute_exists` — fails with `ConditionalCheckFailed` if not exists (descriptor) |
| `entity.delete(key)` | `EntityDelete` | Delete an item (descriptor). Releases only the unique sentinels the item owns. On a `retain` entity it reads the item and deletes it in one transaction with a snapshot of its final state, so an item created again continues past it. A delete that reads first and has no `.condition()` is retried from a fresh read after a concurrent write |
| `entity.deleteIfExists(key)` | `EntityDelete` | Delete with `attribute_exists` — fails with `ConditionalCheckFailed` if not exists (descriptor). On an entity whose delete reads first, retried after a concurrent write like an unconditioned delete |
| `entity.query.<indexName>(pk)` | `Query<Record>` | Query a specific index by partition key (descriptor) |
| `entity.scan()` | `Query<Record>` | Full table scan filtered by entity type (descriptor) |
| `entity.versions(key)` | `Query<Record>` | Query version history for an item (requires `versioned: { retain: true }`) (descriptor). With sort key composites, only the named item's history |
| `entity.deleted.list(key)` | `Query<Record>` | List soft-deleted items for a key (requires `softDelete`) (descriptor) |
| `entity.batchGet(keys)` | See Batch module | Batch get items |
| `entity.batchPut(items)` | See Batch module | Batch put items |
| `entity.batchDelete(keys)` | See Batch module | Batch delete items |

:::caution[A note for Effect v3 users]
`entity.get`, `entity.put`, `entity.update`, and `entity.delete` return Yieldable **operation descriptors** (`EntityOp` / `EntityDelete`), not `Effect`s directly. This mirrors the Effect v4 convention where types like `Option` are also Yieldable-only — `yield* op` works inside `Effect.gen`, but `op.pipe(Effect.map(...))` will not compile.

```typescript
// ✅ Works — yieldable in Effect.gen
yield* UserEntity.get({ userId: "u-1" })

// ❌ Does not compile — descriptor is not an Effect
UserEntity.get({ userId: "u-1" }).pipe(Effect.map(/* … */))

// ✅ Convert to Effect explicitly when needed
UserEntity.get({ userId: "u-1" }).asEffect().pipe(Effect.map(/* … */))
```

**The recommended path is to access entities through `DynamoClient.make()`** — the resulting `BoundEntity` (`db.entities.UserEntity`) auto-wraps each operation into a real `Effect<A, E, never>`, so you get straightforward `Effect.map`/`Effect.flatMap`/`pipe` ergonomics without ever calling `.asEffect()`. Reach for raw entity descriptors only when you need an alternate decode mode (`asRecord`/`asItem`/`asNative`). Composing into a `Transaction` or `Batch` no longer requires them: the bound write builders (`put`/`create`/`delete`/`deleteIfExists`) and the bound `get` are all accepted directly.
:::

### Client Gateway Pattern

`DynamoClient.make({ entities, aggregates?, tables? })` resolves dependencies and returns a typed client with executable operations for all listed entities and aggregates, namespaced under `entities`, `aggregates`, `collections`, and `tables`:

```typescript
const MainTable = Table.make({ schema: AppSchema, entities: { UserEntity } })
const db = yield* DynamoClient.make({
  entities: { UserEntity },
  tables: { MainTable },
})
const users = db.entities.UserEntity
```

**Bound entity methods:**

| Method | Description |
|--------|-------------|
| `bound.get(key)` | Get a single item |
| `bound.put(input, ...combinators)` | Insert or overwrite. Optional combinators (e.g. `condition(...)`). A put over an existing item of a versioned or unique-constrained entity continues it (see `entity.put`) |
| `bound.create(input, ...combinators)` | Insert only — fails with `ConditionalCheckFailed` if exists |
| `bound.upsert(input, ...combinators)` | Create or update — `if_not_exists()` for immutable fields, createdAt, version. Reads first on an entity with unique constraints or `retain` (see `entity.upsert`) |
| `bound.update(key, ...combinators)` | Update an item — compose with `Entity.set(...)`, `Entity.expectedVersion(...)`, etc. |
| `bound.patch(key, ...combinators)` | Update with `attribute_exists` — fails if item does not exist |
| `bound.delete(key, ...combinators)` | Delete an item. Optional combinators (e.g. `condition(...)`) |
| `bound.deleteIfExists(key, ...combinators)` | Delete with `attribute_exists` — fails if item does not exist |
| `bound.paginate(query, ...combinators)` | Execute a query and return a lazy `Stream<A>` of items, automatically paginating |
| `bound.collect(query, ...combinators)` | Execute a query and collect all pages into `Effect<Array<A>>` |

**Bound lifecycle methods** (require matching entity config):

| Method | Requires | Returns | Description |
|--------|----------|---------|-------------|
| `bound.getVersion(key, version)` | `versioned: { retain: true }` | `Effect` | Get a specific version snapshot |
| `bound.versions(key)` | `versioned: { retain: true }` | `BoundQuery` | List all version snapshots as a fluent BoundQuery — supports `.collect()`, `.fetch()`, `.paginate()`, `.count()`, `.limit()`, `.reverse()`, `.startFrom()`, `.filter()`, `.select()` |
| `bound.restore(key)` | `softDelete` | `Effect` | Restore a soft-deleted item |
| `bound.purge(key)` | Any | `Effect` | Permanently remove item + all versions and soft-deleted copies, and release the unique sentinels they own. With sort key composites, only the named item's rows; without, every row of this entity in the partition. Never another entity's rows. Deletes in `BatchWriteItem` chunks of 25, resending unprocessed deletes with `Batch.write`'s backoff; not atomic, so when retries run out the `DynamoError` says exactly how many rows it had deleted |
| `bound.deleted.get(key)` | `softDelete` | `Effect` | Get a specific soft-deleted item |
| `bound.deleted.list(key)` | `softDelete` | `BoundQuery` | List all soft-deleted tombstones in the partition as a fluent BoundQuery |

**Entity definition lifecycle operations** (require matching config — listed in Operations table above for query descriptors):

| Operation | Requires | Description |
|-----------|----------|-------------|
| `entity.getVersion(key, version)` | `versioned: { retain: true }` | Get a specific version snapshot (descriptor) |
| `entity.deleted.get(key)` | `softDelete` | Get a soft-deleted item (descriptor) |
| `entity.restore(key)` | `softDelete` | Restore a soft-deleted item (descriptor) |
| `entity.purge(key)` | Any | Delete the item, its versions and its soft-deleted copies (descriptor): every row of this entity in the partition without sort key composites, the named item's rows with them; never another entity's rows |

### Operation Combinators

These functions transform entity operations via pipe:

| Export | Works On | Description |
|--------|----------|-------------|
| `set(updates)` | `EntityUpdate` | Set fields to new values (dual API) |
| `expectedVersion(n)` | `EntityUpdate` | Optimistic lock — fail if version doesn't match. Requires a `versioned` entity: on any other it fails with a `ValidationError` before anything is sent |
| `consistentRead` | `EntityGet` | Enable strongly consistent reads |
| `condition(input)` | `EntityPut`, `EntityUpdate`, `EntityDelete` | Add a `ConditionExpression`. A later one replaces an earlier one. It is ANDed with the op's own guard (`create`'s not-exists, `patch`'s and `deleteIfExists`'s exists), never in its place. An empty condition (`{}`, `and()`) is no condition. An empty part under `or()` or `not()`, or an `or()` with no parts, fails with a `ValidationError` before anything is sent. An `isIn` with no values is sent, and DynamoDB's rejection of its `IN ()` is a `ValidationError` naming it |
| `remove(fields)` | `EntityUpdate` | REMOVE attributes from the item |
| `add(values)` | `EntityUpdate` | Atomically ADD to numeric attributes |
| `subtract(values)` | `EntityUpdate` | Subtract from numeric attributes (SET `#f = #f - :v`) |
| `append(values)` | `EntityUpdate` | Append to list attributes (`list_append`) |
| `deleteFromSet(values)` | `EntityUpdate` | DELETE elements from Set attributes |
| `returnValues(mode)` | `EntityUpdate`, `EntityDelete` | Control DynamoDB `ReturnValues`. An update takes `"none" \| "allOld" \| "allNew" \| "updatedOld" \| "updatedNew"`; a delete takes `"none" \| "allOld"` (any other mode fails with a `ValidationError` before sending). On an update the result type follows the mode (`UpdateReturn<A, M>`): `"none"` → `undefined`, `"updatedOld"` / `"updatedNew"` → a `Partial` of the top-level attributes the update wrote, `"allOld"` / `"allNew"` → the whole item. Honoured on every update path; with repeated calls the last one wins. On a delete, `"allOld"` returns the deleted item (`undefined` when there was none) on every delete path, and `"none"` nothing; a deleted item that won't decode is `DeleteAppliedButUnreadable` (the delete was applied) |
| `cascade(config)` | `EntityUpdate` | Propagate source entity changes to target entities that embed it via `DynamoModel.ref`. Config: `{ targets, filter?, mode? }` (dual API) |

### Decode Mode Selectors

Control what type an operation returns:

| Export | Returns | Description |
|--------|---------|-------------|
| `asModel` | `Entity.Model<E>` | Pure domain object (default for `yield*`) |
| `asRecord` | `Entity.Record<E>` | Domain + system fields (version, timestamps) |
| `asItem` | `Entity.Item<E>` | Full DynamoDB item (all keys + `__edd_e__`) |
| `asNative` | `Entity.Marshalled<E>` | Raw DynamoDB `AttributeValue` format |

### Type Extractors

| Type | Description |
|------|-------------|
| `Entity.Model<E>` | Pure domain object fields |
| `Entity.Record<E>` | Model + system metadata (version, timestamps) |
| `Entity.Input<E>` | Creation input (model fields, no system fields) |
| `Entity.Update<E>` | Mutable fields only (keys and immutable excluded) |
| `Entity.Key<E>` | Primary key attributes only |
| `Entity.Item<E>` | Full DynamoDB item (model + system + keys + `__edd_e__`) |
| `Entity.Marshalled<E>` | DynamoDB `AttributeValue` format |

### Schema & Attribute Accessors

| Export | Description |
|--------|-------------|
| `keyAttributes(entity)` | List all key attribute names (primary + GSI) |
| `keyFieldNames(entity)` | List physical field names for all keys |
| `compositeAttributes(entity)` | List all composite attribute names across indexes |
| `itemSchema(entity)` | Get the item-level decode schema |
| `decodeMarshalledItem(entity, item)` | Decode a DynamoDB item (DynamoDB JSON with `B` as bytes or base64, or already unmarshalled) as a table read does: packed fields by stored form, sparse maps rebuilt, renames reversed. Fails with `ValidationError` (a missing compressor's `cause` is `CompressorNotRegistered`) |

### Usage

```typescript
const UserEntity = Entity.make({
  model: User,
  entityType: "User",
  primaryKey: {
    pk: { field: "pk", composite: ["userId"] },
    sk: { field: "sk", composite: [] },
  },
  indexes: {
    byEmail: {
      name: "gsi1",
      pk: { field: "gsi1pk", composite: ["email"] },
      sk: { field: "gsi1sk", composite: [] },
    },
  },
  timestamps: true,
  versioned: true,
  unique: { email: ["email"] },
})

// Get typed client with executable operations
const db = yield* DynamoClient.make({
  entities: { UserEntity },
  tables: { MainTable },
})
const users = db.entities.UserEntity

// CRUD
const user = yield* users.put({ userId: "u-1", email: "a@b.com", ... })
const found = yield* users.get({ userId: "u-1" })

// Update with combinators
yield* users.update({ userId: "u-1" }, Entity.set({ email: "new@b.com" }))

// Update with multiple combinators
yield* users.update(
  { userId: "u-1" },
  Entity.set({ email: "new@b.com" }),
  Entity.expectedVersion(1),
)

yield* users.delete({ userId: "u-1" })

// Query execution via bound entity
const allUsers = yield* users.collect(UserEntity.query.byEmail({ email: "a@b.com" }))
const stream = users.paginate(UserEntity.scan(), Query.pageSize(100))

// Or with v2 entity-centric pattern (BoundQuery fluent API):
// const db = yield* DynamoClient.make({ entities: { UserEntity } })
// const allUsers = yield* db.entities.UserEntity.byEmail({ email: "a@b.com" }).collect()
```

See [Getting Started](/effect-dynamodb/getting-started/) and [Modeling](/effect-dynamodb/guides/modeling/) for details.

## Query

Pipeable `Query<A>` data type — a lazy, immutable description of a DynamoDB query or scan.

```typescript
import { Query } from "effect-dynamodb"
```

### Combinators

| Export | Type | Description |
|--------|------|-------------|
| `where(conditions)` | Dual | Add sort key conditions (`KeyConditionExpression`) |
| `limit(n)` | Dual | Return at most `n` items (a contract on results — accumulates across requests, works under a filter) |

## BoundQuery

The fluent query builder returned by every entity query accessor on a `BoundEntity` (e.g. `db.entities.Tasks.byProject({...})`) and by `db.entities.Tasks.scan()`. `BoundQuery<Model, SkRemaining, A>` wraps an internal `Query<A>` with pre-resolved services so all terminals return `Effect<..., ..., never>`.

```typescript
import type { BoundQuery } from "effect-dynamodb"
```

Combinators are immutable — each call returns a new `BoundQuery`. Terminals execute the query.

### Combinators

| Method | Description |
|--------|-------------|
| `.where((t, ops) => …)` | Type-safe sort key condition on remaining SK composites. Only available when SK composites have not all been consumed. Consumes `SkRemaining` (cannot be called twice). Operators: `eq`, `lt`, `lte`, `gt`, `gte`, `between`, `beginsWith`. |
| `.filter((t, ops) => …)` | Post-read filter expression via callback. Type-safe attribute paths via `t`, condition operators via `ops`. An empty filter (`and()`) is no filter. An empty part under `or()` or `not()`, or an `or()` with no parts, fails with a `ValidationError` before sending. An `isIn` with no values is sent, and DynamoDB's rejection is a `ValidationError` (`operation: "query.filter"`) naming it. |
| `.filter(shorthand)` | Post-read filter via an equality shorthand object: `{ status: "active" }` ANDs `status = "active"` for each key. For other comparisons use the callback form. |
| `.select((t) => […paths])` | Projection expression via callback. Returns `BoundQuery<…, Record<string, unknown>>`. |
| `.select(["field", …])` | Projection via attribute name array. |
| `.limit(n)` | Return at most `n` items. A contract on results: the query accumulates across as many requests as it takes, which is what makes it work under `.filter()`. |
| `.pageSize(n)` | Fetch in batches of `n` rows — sets DynamoDB's `Limit`. A contract on round trips, not on what comes back. |
| `.maxPages(n)` | Maximum number of DynamoDB pages to fetch. |
| `.reverse()` | Reverse sort order (`ScanIndexForward = false`). |
| `.startFrom(cursor)` | Resume pagination from an opaque cursor returned by `.fetch()`. |
| `.consistentRead()` | Enable strongly consistent reads. On a GSI, which DynamoDB reads only eventually consistently, DynamoDB rejects the query and it fails with a `ValidationError` naming the index. An entity's indexes are GSIs when `db.tables.*.create()` creates them. |
| `.ignoreOwnership()` | Skip the `__edd_e__` entity-type filter. Use only when querying a polymorphic GSI shared across entity types and you want every item back. |

### Terminals

| Method | Returns |
|--------|---------|
| `.collect()` | `Effect<Array<A>, DynamoClientError \| ValidationError, never>` — drain all pages into a single array. |
| `.fetch()` | `Effect<Page<A>, DynamoClientError \| ValidationError, never>` — single page + opaque cursor. `Page<A>` is `{ items: Array<A>, cursor: string \| undefined }`. |
| `.paginate()` | `Stream<A, DynamoClientError \| ValidationError, never>` — lazy stream that paginates automatically. |
| `.count()` | `Effect<number, DynamoClientError, never>` — count-only query (`Select: COUNT`); items are not returned. |

### `where` typing

`.where()` is conditionally available based on the `SkRemaining` type parameter. When the index's SK composites have already been fully consumed (e.g., the entity has no SK composites, or all of them were supplied to the query accessor), `.where()` is **not present** on the type — calling it is a compile error. Once called, `.where()` consumes `SkRemaining` and the resulting `BoundQuery` no longer exposes `.where()`.

### Usage

```typescript
const db = yield* DynamoClient.make({ entities: { Tasks } })

// Sort key condition + filter + limit
const recent = yield* db.entities.Tasks
  .byProject({ projectId: "p-1" })
  .where((t, { beginsWith }) => beginsWith(t.createdAt, "2026"))
  .filter((t, { eq }) => eq(t.status, "active"))
  .limit(50)
  .collect()

// Single page + cursor
const page = yield* db.entities.Tasks
  .byProject({ projectId: "p-1" })
  .fetch()

// Lazy stream
yield* db.entities.Tasks
  .byProject({ projectId: "p-1" })
  .paginate()
  .pipe(Stream.runForEach((task) => Console.log(task.title)))

// Count only
const total = yield* db.entities.Tasks.byProject({ projectId: "p-1" }).count()
```

See [Queries](/effect-dynamodb/guides/queries/) and [Expressions](/effect-dynamodb/guides/expressions/) for details.

## Collections

Multi-entity queries across a shared index. Collections are **auto-discovered** from entity indexes that share the same `collection` property.

### Auto-Discovery

When multiple entities define the same `collection` name on the same GSI, they are automatically grouped into a collection accessible via `db.collections.<name>()`:

```typescript
// Define entities with shared collection
const Employees = Entity.make({
  // ...
  indexes: {
    byTenant: {
      collection: "tenantMembers",
      name: "gsi1",
      pk: { field: "gsi1pk", composite: ["tenantId"] },
      sk: { field: "gsi1sk", composite: ["name"] },
    },
  },
})

const Tasks = Entity.make({
  // ...
  indexes: {
    byTenant: {
      collection: "tenantMembers",
      name: "gsi1",
      pk: { field: "gsi1pk", composite: ["tenantId"] },
      sk: { field: "gsi1sk", composite: ["priority"] },
    },
  },
})

// Auto-discovered on the typed client
const db = yield* DynamoClient.make({ entities: { Employees, Tasks } })
const result = yield* db.collections.tenantMembers({ tenantId: "t-1" }).collect()
// result: { Employees: Employee[], Tasks: Task[] }
```

A collection query takes `.filter()`, `.select()`, `.limit()`, `.pageSize()`, `.reverse()` and `.startFrom()`, and keeps its grouping through them. Its terminals:

| Terminal | Returns |
|----------|---------|
| `.collect()` | The grouped result, `{ Employees: Employee[], Tasks: Task[] }` |
| `.fetch()` | One page, grouped the same way, with its `cursor` |
| `.paginate()` | A `Stream` of every item, each tagged with its member: `{ member: "Employees", item: Employee }` (`CollectionStreamItem`) |
| `.count()` | The number of items, every member's together |

A filter or select names each member's **domain** fields: on a member that stores a field under another name (`DynamoModel.configure(..., { field })`) it reads that attribute. A member without the field reads it as absent — `eq` doesn't match, `not(eq(...))` and `notExists(...)` do — and an attribute it stores under that name never stands in for the field. `.select()` returns partial records grouped per member. The query also takes `.maxPages()`, `.ignoreOwnership()` and `.consistentRead()`. A collection over a GSI, which DynamoDB reads only eventually consistently, fails `.consistentRead()` with a `ValidationError` naming the index, from DynamoDB's rejection. Its types (`CollectionQuery`, `CollectionStreamItem`, `CollectionSelected`, `CollectionAccessors`) are exported.

### Explicit Collections

For advanced use, `Collection.make()` creates collections explicitly:

```typescript
import { Collection } from "effect-dynamodb"
```

| Export | Type | Description |
|--------|------|-------------|
| `make` | `(name, entities) => Collection` | Create a collection from entities sharing an index |

See [Indexes & Collections](/effect-dynamodb/guides/indexes/) for details.

## Transaction

Atomic multi-item operations.

```typescript
import { Transaction } from "effect-dynamodb"
```

| Export | Type | Description |
|--------|------|-------------|
| `transactGet` | `(items) => Effect<Tuple>` | Atomically get up to 100 items — returns a typed tuple. Accepts unbound `Entity.get` intermediates AND the `BoundGet` returned by `db.entities.*.get(...)` |
| `transactWrite` | `(ops) => Effect<void>` | Atomically write up to 100 items (puts, updates, deletes, condition checks). A put of a versioned or unique-constrained entity reads the item first and creates or replaces it as the entity's own `put` does; an `update` / `patch`, and a delete of a `unique` / `retain` / `softDelete` entity, write exactly what the entity's own op writes (see below). Accepts unbound `Entity.put`/`Entity.update`/`Entity.delete` intermediates AND the bound builders returned by `db.entities.*`; conditions attached to either (including `create()`'s implicit `attribute_not_exists`) are compiled into the transact item. `upsert` is rejected with a `ValidationError` — see below |
| `check` | `(get, condition) => ConditionCheckOp` | Create a condition-check operation for `transactWrite` (dual API). Takes either get spelling |

### transactGet

```typescript
const [user, order] = yield* Transaction.transactGet([
  UserEntity.get({ userId: "u-1" }),
  db.entities.Orders.get({ orderId: "o-1" }),
])
```

`db.entities.X.get(key)` returns a `BoundGet`: it **is** an `Effect<Model, …, never>` (yield it, pipe it, `Effect.catchTag` it) and it is *also* a read descriptor, so the same value works in `transactGet`, `Batch.get` and `check`. That matters most for entities authored with the pure, AWS-free `@effect-dynamodb/schema` package — a pure definition carries no operations, so the bound client is the only surface its author holds. Both spellings unwrap through one protocol and can be mixed in a single array; anything else fails with a `ValidationError` carrying **EDD-9052**.

### transactWrite

```typescript
yield* Transaction.transactWrite(
  UserEntity.put({ userId: "u-1", ... }),
  OrderEntity.delete({ orderId: "o-old" }),
  Transaction.check(
    UserEntity.get({ userId: "u-1" }),
    { attributeExists: "email" },
  ),
)
```

### Ops `transactWrite` will not compile

`transactWrite` compiles each op to a `Put`, `Delete` or `ConditionCheck`, plus the extra items of a guarded put, and plans updates and multi-item deletes from the entity's own op (see below). An op whose entity contract needs a different verb, extra items it can't build from the op, or a service the compile step does not hold is refused with a `ValidationError` rather than written with different semantics:

| Op / entity feature | Why it is refused |
|---|---|
| `upsert()` | An `UpdateItem` using `if_not_exists` for `createdAt`, immutable fields and the version counter. A `Put` would reset all three |
| `put()` / `create()` of an entity with `refs` | Write-time ref hydration reads the referenced entity; the put compile step cannot, so the ref attribute would be written empty. (An `update()` is planned from the entity's own update, which hydrates refs as it does standalone.) |
| `generatedId` | Id generation needs the `Crypto` service |
| `vectorIndexes` | Computing the embedding needs the `Embedder` service; the item would drop out of the index |
| `update()` with `.cascade(...)` | **EDD-9059.** A cascade is a follow-up write to other entities after the update commits, so it cannot share the transaction |
| `update()` / `delete()` with a `.returnValues(...)` mode that returns an item | **EDD-9060.** A transaction returns no item attributes. (A delete with such a mode is not a transact op at the type level either.) |
| `update()` of an entity with `vectorIndexes` | **EDD-9061.** Recomputing the embedding needs the `Embedder` service |

### Guarded puts expand

A `put` through `transactWrite` (or `EventStore.append({ additionalItems })`) of a versioned or unique-constrained entity is written exactly as the entity's own `put` writes it. It reads the item first, then emits **more than one item**, all atomic with the rest of the transaction: the row, guarded on what was read (missing: `attribute_not_exists`; present: its version and incarnation, or its unique values), one `attribute_not_exists`-guarded sentinel per new unique value, a release of each old sentinel the item owns, and with `retain` the snapshot.

Consequences worth knowing:

- **An existing item is replaced, not refused.** It continues its version, incarnation and `createdAt`, its replaced state is snapshotted (`retain`), and changed unique values rotate their sentinels. A deleted retain item created again continues after its retained version history. This is what keeps a versioned read model in step with `EventStore.append`.
- **A race is retried.** If another writer changes, creates or deletes the item between the read and the transaction, or a sentinel it releases changes hands, the transaction is cancelled and built again from a fresh read. A race lost on every attempt fails with `OptimisticLockError` / `ConcurrentModification`.
- **Errors name what happened.** A duplicate fails with `UniqueConstraintViolation` (naming the constraint and the values). Only an op's own condition (`.condition()`, `create()`) is reported as a condition: `TransactionCancelled` from `transactWrite`, `AdditionalItemConditionFailed` from `append`.
- **One op per item.** DynamoDB allows one operation per item in a transaction, and rejects a transaction that touches one item twice; it fails with a `ValidationError` naming the entity and both ops, and nothing is written. That includes two puts of one item, and two puts that swap unique values: each releases the sentinel the other reserves. In `append`, an additional item that repeats an event or the idempotency sentinel fails the same way. DynamoDB can report a repeat as a failed condition, so the repeat is recognised first: it is never read as a lost race and retried. `transactGet` reading one item twice fails with a `DynamoError` naming both gets.
- **Write limits.** Limits and request rules DynamoDB enforces itself (100 items and 4 MB per transaction, 400 KB per item, 2048 bytes per partition key and 1024 per sort key, one operation per item, 4,096 characters / 300 operators per expression and 100 operands per `IN`, no `IN ()`, no empty key values) are not checked before sending. The write is sent; DynamoDB rejects it whole, so nothing is written; the library recognises the rejection, confirms it against the request it sent, and fails with an error naming the culprit, with DynamoDB's error as its `cause`. Over 100 items is `TransactionOverflow` (entity writes), `AppendTooLarge` (`append`), `AggregateTransactionOverflow` (an aggregate group), `CascadePartialFailure` (a transactional cascade) or a `DynamoError` (`transactWrite`, `transactGet`); the others are a `ValidationError` naming the item and its key (an over-long condition also names how much of it is the caller's `.condition()`), or for 4 MB the largest items (by [DynamoDB's size accounting](/effect-dynamodb/guides/data-integrity/#how-dynamodb-sizes-items), which counts each Put's item, each other action's key, and every expression with its names and values; a `retain` put counts twice: its item and its snapshot), with the library's measure beside the size DynamoDB reported. The same diagnosis covers single-item writes, `Batch.write` and `EventStore` snapshots. A rejection the library does not recognise, or cannot confirm by measuring, passes through as DynamoDB's `DynamoValidationError`.
- **The reads cost capacity.** Each guarded put makes one consistent `GetItem` of its item, one more per sentinel it would release, and, for a missing `retain` item, one `Limit 1` query of its version history (plus, with primary sort key composites, a keys-only `Limit 1` query for older history).
- **The 100-item cap counts the expanded total.** Ten `unique` + `retain` puts occupy 30 slots or more. The error message reports both numbers.
- **`softDelete` does not affect a put** — only a delete — so puts of soft-deletable entities are unaffected.

### Updates and multi-item deletes

An `update` / `patch`, and a `delete` of an entity with `unique`, `versioned: { retain: true }` or `softDelete`, write **exactly what the entity's own op writes** — the guarded update or put of the row, sentinel rotations and owned releases, the retain snapshot, the soft-delete tombstone. `transactWrite` runs the op itself with its write recorded instead of sent, and the recorded items join the transaction. So everything the standalone op guarantees holds inside the transaction too:

```typescript
yield* Transaction.transactWrite([
  // Rotates the email sentinel: releases the old value, reserves the new one.
  db.entities.Users.update({ userId: "u-1" }).set({ email: "new@example.com" }),
  // Releases every sentinel the stored row owns.
  db.entities.Vehicles.delete({ vehicleId: "v-9" }),
  // Commits or rolls back with both of the above.
  db.entities.AuditEvents.put({ ... }),
])
```

- **It reads where the standalone op reads** — the row for a read-then-write update or a multi-item delete, owned sentinels, refs, a `clearMap`'s buckets. A plain update compiles to one `Update` item with no read.
- **Read outcomes surface before anything is sent:** `ItemNotFound`, `ConditionalCheckFailed` (`patch` of a missing item), `OptimisticLockError` (a stale `expectedVersion`), `RefNotFound`.
- **A race is retried, as for a guarded put.** The recorded items are guarded on what was read; if the row changes in between, the transaction is cancelled and planned again from a fresh read. With a caller condition (`.condition()`, `patch`, `deleteIfExists`) a cancelled main item is reported as `TransactionCancelled` instead.
- **A taken unique value** is `UniqueConstraintViolation`, naming the constraint and the values.
- **An update with nothing to write** contributes no item; a transaction of only such updates sends nothing.
- `EventStore.append({ additionalItems })` does not plan: it accepts no `update` (at the type level), and refuses these deletes (**EDD-9048**).

## Batch

Batch get and write with auto-chunking and unprocessed item retry.

```typescript
import { Batch } from "effect-dynamodb"
```

| Export | Type | Description |
|--------|------|-------------|
| `get` | `(...gets) => Effect<Tuple>` | Batch-get up to 100 items with typed tuple return. Accepts unbound `Entity.get` intermediates AND the `BoundGet` returned by `db.entities.*.get(...)` |
| `write` | `(...ops) => Effect<void>` | Batch-write any number of items (auto-chunks at 25). Accepts unbound `Entity.put`/`Entity.delete` intermediates AND the bound builders returned by `db.entities.*`; conditional ops and `upsert`/`update`/`patch` are rejected with a `ValidationError` — see below. Puts of a `versioned` entity go first, as create-only transactions of up to 100 items |

### Usage

```typescript
// Batch get — typed positional results; unbound and bound gets may be mixed
const [user1, user2] = yield* Batch.get([
  UserEntity.get({ userId: "u-1" }),
  db.entities.Users.get({ userId: "u-2" }),
])

// Batch write — mixed puts and deletes
yield* Batch.write(
  UserEntity.put({ userId: "u-1", ... }),
  UserEntity.put({ userId: "u-2", ... }),
  OrderEntity.delete({ orderId: "o-old" }),
)
```

Auto-chunking: `get` chunks at 100 items, `write` chunks at 25 items. Both retry unprocessed items automatically.

`BatchWriteItem` has no `ConditionExpression`, so `Batch.write` **rejects** any op carrying a condition — `.condition(...)`, `create()` (implicit `attribute_not_exists`) and `deleteIfExists()` (implicit `attribute_exists`) all fail with a `ValidationError` rather than silently writing unconditionally, whatever `.condition()` is added to them (even `.condition({})`). Use `Transaction.transactWrite` for conditional writes.

It also rejects (**EDD-9049**) any write of an entity configured with `unique` or `versioned: { retain: true }`, and any *delete* of a `softDelete` entity. `BatchWriteItem` has no `ConditionExpression` (which is the entirety of a uniqueness sentinel's correctness), no `UpdateRequest`, and no atomicity across its 25-item chunks — a sentinel that lands without its row, or a row without its sentinel, is a corrupt partition. A **put** of a `softDelete` entity is unaffected, because `softDelete` only changes the delete path.

Puts of a plain `versioned` entity are accepted, but not as `PutRequest`s, which would reset an existing item to version 1 under a new incarnation. `Batch.write` sends them first, as create-only `TransactWriteItems`, each conditioned on `attribute_not_exists`, chunked at exactly 100 items and 4,194,304 bytes by [DynamoDB's size accounting](/effect-dynamodb/guides/data-integrity/#how-dynamodb-sizes-items). A chunk DynamoDB rejects for size all the same fails with a `ValidationError` giving both sizes, and is not re-split. There is no read, so there is no window between a check and the write. A batch that touches such an item more than once is refused with a `ValidationError` before anything is written.

- A put that would replace an existing item cancels its whole chunk, so nothing in that chunk is written, and fails with a `ValidationError`. Earlier chunks may already have been written, since `Batch.write` was never atomic across chunks, and the message says how many; the batch's other requests aren't sent. Use the entity's own `put()` or `Transaction.transactWrite` to replace an item.
- Each chunk costs twice the write capacity of a batch write.
- Contention cancellations (`TransactionConflict`, throttling) are retried with the batch's `maxRetries` / `baseDelayMs` backoff.
- Puts of other entities, and deletes, are still plain `BatchWriteItem` requests.

## EventStore

Typed, Effect-native event sourcing on DynamoDB. Provides a `Decider` model for command-event-state aggregates, an `EventStream` repository per stream type, optimistic concurrency via stream versioning, and a `commandHandler` combinator for the read-decide-append cycle.

```typescript
import { EventStore } from "effect-dynamodb"
```

### Construction

| Export | Description |
|--------|-------------|
| `EventStore.makeStream({ table, streamName, events, streamId, metadata?, snapshot?, casing?, indexes? })` | Create an `EventStream<TEvent, TStreamIdFields, TMetadata, TState, TIndexName, TIndexProjections, TPartitionedIndexName>` bound to a `Table`. `events` is an array of `Schema.TaggedClass` event types, `streamId.composite` lists the stream-id composite fields, optional `metadata` is a Schema. Optional `snapshot` is `{ schema, mode?, every? }` — `mode` is `"after-append"` (default) or `"inline"` (see [Inline snapshots](/effect-dynamodb/tutorials/event-sourcing/#step-17-inline-snapshots-and-readlatest)). Optional `casing` sets the key casing for the stream (stream name, stream ids, command ids); omitted, the stream name is lower-cased and the rest follows the schema — see [Stream key casing](/effect-dynamodb/tutorials/event-sourcing/#stream-key-casing). Optional `indexes` declares stream indexes: `{ [name]: { type?: "lsi" \| "gsi", index, sk, pk?, key: (event, version, streamId) => string \| undefined, partition?: (event, version, streamId) => string \| undefined, snapshot?: (state, asOfVersion, streamId) => { partition, key } \| undefined, projection?: "all" \| "withoutMetadata" \| "keys" } }` — see [Stream indexes](/effect-dynamodb/tutorials/event-sourcing/#step-19-stream-indexes). `partition` and `snapshot` are GSI-only: `partition` derives the index partition (raw) so several streams share one partition of a GSI, and `snapshot` (requires `partition` and a `snapshot` config) puts the stream's snapshot item in it — see [Shared indexes](/effect-dynamodb/tutorials/event-sourcing/#step-22-shared-indexes-across-streams). Within one append, the events' and inline snapshot's partitions must agree (`ValidationError` otherwise). `projection` (default `"all"`) is the DynamoDB index projection, what the index copies from each event (unrelated to inline read-model projections) — see [Index projection](/effect-dynamodb/tutorials/event-sourcing/#index-projection); it must match the deployed index. A malformed entry (including `partition` / `snapshot` on an LSI, or `snapshot` without `partition`), an unknown `projection` or a member an entry does not declare (a misspelled `projection`, also a type error) throws `[EDD-9063]`. Optional `storedAs: { data: DynamoModel.Packed(...) }` stores event data packed, and `snapshot.storedAs` the snapshot state — see [Packed Storage](/effect-dynamodb/guides/packed-storage/#eventstore-streams); any other `storedAs` key throws `[EDD-9079]`. |
| `EventStore.bind(stream)` | Resolve `DynamoClient` and `TableConfig` from context and return a `BoundEventStream` whose operations have `R = never`. Use inside `Context.Service` make effects. |
| `EventStore.indexDefinitions(...streams)` | `CreateTable` fragments for the streams' indexes: `{ AttributeDefinitions, LocalSecondaryIndexes?, GlobalSecondaryIndexes? }`, to merge into your own `CreateTable` input (the table's `pk` / `sk` are not included). Each index's `Projection` follows its `projection`: `"all"` → `ALL`; `"withoutMetadata"` → `INCLUDE` of `__edd_e__`, `data`, `eventType`, `streamId`, `timestamp`, `version`; `"keys"` → `INCLUDE ["__edd_e__"]` (**not** `KEYS_ONLY`: every read filters on `__edd_e__`). Tables deployed with CDK or Terraform must copy this `Projection` exactly; the library migrates nothing. An LSI must be created with the table and caps every partition key value's item collection at 10 GB. Throws `[EDD-9067]` for conflicting definitions of one physical index, including two streams declaring it with different projections. A derived `partition` or a `snapshot` entry is not part of the definition: streams declaring one GSI alike share it, emitted once; a `"withoutMetadata"` index any of them indexes snapshots in also projects `asOfVersion` and `state`. |

### Stream index projection

`projection` on a stream index entry is the DynamoDB index projection (which event attributes the index stores), not an inline read-model projection. Default `"all"`; existing streams are unchanged and the library migrates nothing.

| `projection` | Emitted `Projection` | Index write per event | Read through an LSI | Read through a GSI | `metadata` type |
|---|---|---|---|---|---|
| `"all"` (default) | `ALL` | the full event | one `Query` | one `Query` | the stream's metadata type |
| `"withoutMetadata"` | `INCLUDE` of `__edd_e__`, `data`, `eventType`, `streamId`, `timestamp`, `version` (6 `NonKeyAttributes`) | the event without `metadata` | one `Query` | one `Query` | `undefined` |
| `"keys"` | `INCLUDE ["__edd_e__"]`, not `KEYS_ONLY` (1 `NonKeyAttribute`) | the keys and `__edd_e__` | one `Query` with `Select: ALL_ATTRIBUTES`; DynamoDB fetches each event from the table | one `Query`, then `BatchGetItem` per page (100 keys per request, unprocessed keys retried, missing keys re-read once with `ConsistentRead`, index order kept) | the stream's metadata type |

- `"keys"` trades write and storage cost for read cost: each event read through it costs a table read, rounded up to 4 KB. `Query.count` never fetches.
- `__edd_e__` is always projected: every read filters on it, and DynamoDB refuses a filter on an attribute an index does not project.
- **The declared projection must match the deployed index.** An LSI's projection is fixed at table creation, and a GSI's cannot be updated (delete and re-create it). With CDK or Terraform, copy each `Projection` from `indexDefinitions` exactly. A deployed index without `__edd_e__` fails every read with DynamoDB's "does not project one or more filter attributes" `DynamoValidationError`; one projecting less than an `"all"` / `"withoutMetadata"` declaration fails with a `ValidationError` (`operation: "EventStore.index.decode"`) naming the index.
- See [Index projection](/effect-dynamodb/tutorials/event-sourcing/#index-projection) in the tutorial.

### Operations

`EventStream` and `BoundEventStream` expose the same operations. The only difference is the `R` parameter — `EventStream` ops require `DynamoClient | TableConfig`, `BoundEventStream` ops have `R = never`.

| Method | Returns |
|--------|---------|
| `append(streamId, events, expectedVersion, options?)` | `Effect<AppendResult<TEvent>, AppendError, R>` — atomically append events with optimistic concurrency. `AppendError` is `VersionConflict \| StreamSealed \| DuplicateCommand \| AdditionalItemConditionFailed \| AppendTooLarge \| DynamoClientError \| ValidationError \| TransactionCancelled \| UniqueConstraintViolation \| OptimisticLockError \| ConcurrentModification`; the last three come from guarded puts in `additionalItems`. Each event becomes a `Put` with `attribute_not_exists(pk)` inside a single `TransactWriteItems`. Options: `metadata` (one value written onto every event, validated against the stream's metadata schema) or `eventMetadata` (one entry per event, in order: entry `i` is written onto event `i`, and an `undefined` entry writes no metadata; its length must equal `events.length`) — mutually exclusive, a type error and a `ValidationError` when both are given — plus `eventTimestamps` (one `DateTime` or `undefined` per event, in order: entry `i` is written as event `i`'s `timestamp` in UTC ISO format, `undefined` keeps the append's own time; any length other than `events.length` or a non-`DateTime` entry is a `ValidationError`; combines with either metadata option; the idempotency sentinel and inline snapshot keep the append's time, and `version`, not `timestamp`, orders the stream), `additionalItems`, `idempotency: { commandId, ttl? An append over DynamoDB's transaction limits is rejected whole, so nothing is written, and fails with `AppendTooLarge` (over 100 items) or a `ValidationError` naming the culprit item; it is never split. |
| `appendOp(streamId, events, expectedVersion, options?)` | `StreamAppendOp` — this stream's append as an item of ANOTHER append's `additionalItems` (or a handler's): it commits if and only if that append does. With `seal: true` it closes this stream in the transaction that opens its successor; without it, it is an atomic multi-stream append. A full append of this stream (its contiguity check, event puts, seal marker, optional inline snapshot), enforced independently; `options` is `NestedAppendOptions` (`append`'s options without `additionalItems`, `idempotency` and `headProof`, refused at runtime with `ValidationError`, `EventStore.appendOp`, as are zero events); nothing is built until the outer append runs. Its failures name this stream (`StreamSealed`, terminal, or `VersionConflict`), judged after the outer stream's own and ahead of the other additional items; it cannot be a `headProof` target. In a changeover, its `expectedVersion` is the version the carried-over state was read at, never a fresh read of the head. All items go through the outer append's `DynamoClient`; a bound stream's op resolves its own `TableConfig`. Not accepted by `Transaction.transactWrite` (type error, and `ValidationError` at runtime) — see [A generation changeover](/effect-dynamodb/tutorials/event-sourcing/#a-generation-changeover) |
| `read(streamId, options?)` | `Effect<ReadonlyArray<StreamEvent<TEvent>>, DynamoClientError \| ValidationError, R>` — read all events for a stream in version order. `options` is `ReadOptions` (`{ consistentRead?: boolean }`). A sealing event carries `sealed: true`. |
| `readFrom(streamId, afterVersion, options?)` | `Effect<ReadonlyArray<StreamEvent<TEvent>>, DynamoClientError \| ValidationError, R>` — read events strictly after a given version; `{ toVersion }` stops the key condition at that version (inclusive), `{ consistentRead }` as for `read`. |
| `currentVersion(streamId, options?)` | `Effect<number, DynamoClientError \| ValidationError, R>` — current head version (0 if the stream is empty). |
| `readLatest(streamId, options?)` | `Effect<LatestState<TState, TEvent>, DynamoClientError \| ValidationError, R>` — the snapshot (if any), the events after it (ascending) and the head version, in one `Query` when the snapshot is current. `options` is `ReadLatestOptions`: `consistentRead`, and `verifySnapshot: false` (`mode: "inline"` without `every` only, `[EDD-9068]` otherwise; ignored without a snapshot config) to read the snapshot item alone with one `GetItem`, returning `{ snapshot, events: [], version: asOfVersion }` with an **unverified** `version` (the verified read when there is no snapshot). `seal` is the sealing event when the read found one (any marked event it fetched; with `verifySnapshot: false`, a marked snapshot costs one `GetItem` of the sealing event); an unverified read of a snapshot left unmarked does not report it. `seal.version < version` means events were written past the seal. |

### Command handler

| Export | Description |
|--------|-------------|
| `EventStore.commandHandler(decider, stream, options?)` | Build a `(streamId, command, options?) => Effect<CommandHandlerResult, …, R>` that loads (strongly consistent by default), decides, folds the new events and appends atomically. Dual API: `commandHandler(decider, stream)` (data-first) or `stream.pipe(EventStore.commandHandler(decider))` (data-last). Works with both `EventStream` (R = `DynamoClient \| TableConfig`) and `BoundEventStream` (R = `never`). On a no-op command (`decide` returns `[]`) the handler returns the current state and version without writing. A load that finds the stream sealed fails with `StreamSealed` before `decide` (after `DuplicateCommand` for a committed `commandId`, ahead of an If-Match mismatch). |

Handler options (`CommandHandlerOptions`):

| Option | Description |
|--------|-------------|
| `retry` | A number or `Schedule`; re-runs the whole load–decide–append cycle on `VersionConflict` only. Default: no retry. `StreamSealed` and `DuplicateCommand` are terminal. A `VersionConflict` naming another stream (an `appendOp` in `additionalItems`) is retried even with an `expectedVersion`, whose If-Match is checked again on the reload |
| `idempotency` | `{ ttl? }` — makes a per-call `commandId` required and writes a dedup sentinel with the events |
| `consistentRead` | Load state with strongly consistent reads. Default `true` |
| `loadState` | `(streamId) => Effect<Option<LoadedState<State>>, EL, RL>` — load the state and head from the caller's own record instead of the stream; `None` is a new stream (initial state, version 0). The If-Match check, `decide` and the append run as before, a `VersionConflict` re-runs it under `retry`, and a no-op or domain error is answered from the record. `EL` / `RL` join the handler's error and requirements (a bound handler's only ones). Read strongly consistent. A `version` that is not a non-negative integer, or a result that is not an `Option`, is a `ValidationError` (`EventStore.commandHandler.loadState`), never retried. Return `sealedVersion` for a sealed stream: the handler fails with `StreamSealed` before `decide` (a `sealedVersion` that is not a non-negative integer, or is below `version`, is a `ValidationError`). Without `headProof` the append keeps the contiguity check. The snapshot is not read: with `every`, one is written when an append crosses a multiple of `every`. With `verifySnapshot: false` or `headProof: "snapshot"`, creating the handler throws `[EDD-9085]` — see [Step 23](/effect-dynamodb/tutorials/event-sourcing/#step-23-state-from-your-own-record) |
| `headProof` | `{ additionalItem: n }` or `"snapshot"` — the `append` `headProof` for every append the handler makes. `{ additionalItem: n }`: every call that appends must return `additionalItems[n]`, conditioned on the loaded version (`ValidationError` otherwise). `"snapshot"`: a `mode: "inline"` stream without `every` only (`[EDD-9085]` when the handler is created otherwise), applied when the load found the snapshot at the head (a verified load with no event after it, or an unverified one); otherwise that append writes the check. Default: the check is written — see [Proving the head with the snapshot](/effect-dynamodb/tutorials/event-sourcing/#proving-the-head-with-the-snapshot) |
| `verifySnapshot` | Default `true`. `false` loads state from the snapshot item alone (one `GetItem`) on a `mode: "inline"` stream without `every`; any other snapshot config throws `[EDD-9068]` when the handler is created, and a stream without one ignores it. Only a successful append is returned unconfirmed: a domain error, a no-op or an append conflict is checked against the head (one `Query` for events after the snapshot's version, which reads no items while the snapshot is current, or a verified load after an append conflict without `expectedVersion`). Falls back to a verified load when the snapshot is missing and before an If-Match mismatch is reported; an If-Match at a lagging snapshot's version answers as the verified load would (`DuplicateCommand`, or `VersionConflict` with the head as `actualVersion`). Without `expectedVersion`, a stale snapshot makes `decide` (and a function-form `additionalItems`, when both decisions append) run a second time on the verified state; a snapshot at the head after an append conflict is a race left to `retry` |

Per-call options (`CommandOptions`):

| Option | Description |
|--------|-------------|
| `metadata` | One metadata value written onto every event the decision appends, validated against the stream's metadata schema. Fixed before `decide` runs |
| `eventMetadata` | A function of the `Decision` returning one metadata entry per event (`undefined` for none), directly or as an `Effect` whose error and requirements join the handler's. Runs after the fold and before a function-form `additionalItems`; not called on a no-op; re-run on every attempt. A result of the wrong length fails with `ValidationError` (`EventStore.commandHandler.eventMetadata`), never retried. Mutually exclusive with `metadata` — see [Event metadata](/effect-dynamodb/tutorials/event-sourcing/#step-20-event-metadata) |
| `eventTimestamps` | A function of the `Decision` returning one `DateTime` per event (`undefined` keeps the append's own time), passed to `append` as `eventTimestamps`. Returns the array directly or an `Effect` of it, whose error and requirements join the handler's (its own `E4` / `R4`); a failure of the `Effect` is not retried. Runs after `eventMetadata` and before a function-form `additionalItems`; not called on a no-op; re-run on every attempt. A result of the wrong length or with a non-`DateTime` entry fails with `ValidationError` (`EventStore.commandHandler.eventTimestamps`), never retried. Combines with either metadata option — see [Original event times](/effect-dynamodb/tutorials/event-sourcing/#original-event-times) |
| `commandId` | The delivery's id; required with `idempotency` |
| `expectedVersion` | If-Match: a loaded version other than this fails with `VersionConflict` (carrying `actualVersion`) before `decide` runs. Never retried |
| `additionalItems` | A static array of transact ops, or a function of the `Decision` (`{ events, state, previous, version }`) returning the ops or an `Effect` of them, committed in the same transaction as the events. The ops are `AppendWriteOp`s: another stream's `appendOp` rides here too, its `expectedVersion` taken from the decision |

### Usage

```typescript
import { EventStore } from "effect-dynamodb"
import { Effect, Schema, Context } from "effect"

class MatchStarted extends Schema.TaggedClass<MatchStarted>()("MatchStarted", {
  venue: Schema.String,
}) {}

class InningsCompleted extends Schema.TaggedClass<InningsCompleted>()("InningsCompleted", {
  innings: Schema.Number,
  runs: Schema.Number,
}) {}

const MatchEvents = EventStore.makeStream({
  table: EventsTable,
  streamName: "Match",
  events: [MatchStarted, InningsCompleted],
  streamId: { composite: ["matchId"] },
})

const decider = {
  initialState: { innings: 0, totalRuns: 0 },
  decide: (cmd: { _tag: "Start"; venue: string }, _state) =>
    Effect.succeed([new MatchStarted({ venue: cmd.venue })]),
  evolve: (state, event) => {
    if (event._tag === "MatchStarted") return state
    return { innings: event.innings, totalRuns: state.totalRuns + event.runs }
  },
}

class MatchEventService extends Context.Service<MatchEventService>()(
  "@app/MatchEventService",
  {
    make: Effect.gen(function* () {
      const stream = yield* EventStore.bind(MatchEvents)
      const handle = EventStore.commandHandler(decider, stream)
      return {
        start: (matchId: string, venue: string) =>
          handle({ matchId }, { _tag: "Start", venue }),
        history: (matchId: string) => stream.read({ matchId }),
      }
    }),
  },
) {}
```

| `ShardIteratorExpired` | `operation`, `cause` | `DynamoStreamsClient` (`ExpiredIteratorException`); the feed re-acquires |
| `StreamDataTrimmed` | `operation`, `cause` | `DynamoStreamsClient` (`TrimmedDataAccessException`) |
| `ChangeFeedTrimmed` | `streamArn`, `shardId`, `sequenceNumber`, `cause` | The feed: a shard's position is past the stream's retention, or a shard it still owed records from has left the stream — records were lost |
| `ChangeFeedLeaseHeld` | `streamArn`, `consumer`, `owner`, `expiresAt` | Another process holds the lease |
| `ChangeFeedLeaseLost` | `streamArn`, `consumer`, `owner` | The lease was taken over while running; also an acknowledgement made after the lease was lost |
| `CheckpointStoreError` | `operation`, `cause` | A checkpoint store operation failed |

`DynamoStreamsClient` maps `LimitExceededException` to `ThrottlingError`, and otherwise uses the shared `DynamoValidationError`, `InternalServerError`, `ResourceNotFoundError` and `DynamoError`. `ChangeFeedError` is those (less the two iterator errors), `ChangeFeedTrimmed`, the lease errors and `CheckpointStoreError`.

## StorageEncoding

Helpers for [packed storage](/effect-dynamodb/guides/packed-storage/). Compressors come from the `Compression` service in context; none of these adds a requirement. The Effect forms cost one Effect per call and look the registry up only for a compressed value; to decode many values with no Effect per value, resolve the registry once (`yield* Effect.serviceOption(Compression)`) and call a `*Sync` twin in a loop.

```typescript
import { StorageEncoding } from "effect-dynamodb"
```

| Export | Type | Description |
|--------|------|-------------|
| `encode` | `(storedAs, wire) => Effect<AttributeValue \| undefined, ValidationError>` | The `AttributeValue` a wire (encoded) value is stored as: `S`, `B`, `NULL`, or `undefined` for no attribute |
| `decode` | `(stored: AttributeValue) => Effect<unknown, ValidationError>` | Read a stored `AttributeValue` (DynamoDB JSON) by its form (native, `S`, `B` as bytes or base64) and return its wire form as plain JSON |
| `decodeUnmarshalled` | `(stored: unknown) => Effect<unknown, ValidationError>` | The same for an already-unmarshalled value: a JSON string, bytes or base64 text, or a native value returned unchanged |
| `valueBytes` | `({ schema, value, storedAs? }) => Effect<number, ValidationError>` | The DynamoDB size of one attribute value as stored: packed under `storedAs`, or as a native map when it is omitted |
| `valueBytesSync` | `({ schema, value, storedAs?, compressors? }) => number` | `valueBytes`, synchronously, for pure planning code: the schema encode runs synchronously, compressors are passed in (none by default), and a failure throws the `ValidationError` `valueBytes` fails with |
| `encodeSync` / `decodeSync` / `decodeUnmarshalledSync` | `(…, options?: { compressors? }) => …` | Synchronous twins of `encode` / `decode` / `decodeUnmarshalled` for pure code: compressors are passed explicitly (a `Compression.make(...)` registry or a list; none by default) and a failure **throws** the `ValidationError` the Effect form fails with |
| `limits` | `{ item: 409_600, transaction: 4_194_304 }` | DynamoDB's item and `TransactWriteItems` size limits, in bytes |

## Compression

| Export | Description |
|--------|-------------|
| `Compressor` | `{ codec: "gzip" \| "brotli" \| "zstd", compress(input: Uint8Array): Uint8Array, decompress(input: Uint8Array): Uint8Array }` — a synchronous codec implementation |
| `Compression` | `Context.Service` holding a `CompressionRegistry` (`get(codec)`, `codecs`). `Compression.layer(compressors)` provides one; `Compression.make(compressors)` builds one (throws `[EDD-9078]` on two compressors for one codec or an unknown codec); `Compression.empty` has none |

`node:zlib`-backed implementations, from the `effect-dynamodb/compression/zlib` entry point (the only module that imports `node:zlib`):

```typescript
import * as ZlibCompression from "effect-dynamodb/compression/zlib"
```

| Export | Description |
|--------|-------------|
| `gzip({ level?, maxOutputLength? })` | gzip `Compressor` |
| `brotli({ quality?, maxOutputLength? })` | brotli `Compressor` (text mode) |
| `zstd({ level?, maxOutputLength? })` | zstd `Compressor`, level 3 by default. Needs Node 22.15 or later; throws when created on older Node |
| `available({ maxOutputLength? })` | gzip and brotli, plus zstd when this runtime has it |
| `DEFAULT_MAX_OUTPUT_LENGTH` | `67_108_864` (64 MiB), the default `maxOutputLength` |
| `hasZstd()` | `true` when this runtime has zstd |

`maxOutputLength` caps one value's decompressed size: 64 MiB by default (`DEFAULT_MAX_OUTPUT_LENGTH`), any positive integer to change it, `Infinity` for Node's own limit only. Going over it fails the read with a `ValidationError`.

## Errors

Tagged error types for precise error handling with `catchTag`.

```typescript
import {
  DynamoError, ThrottlingError, DynamoValidationError,
  InternalServerError, ResourceNotFoundError,
  ItemNotFound, ConditionalCheckFailed,
  ValidationError, TransactionCancelled, TransactionOverflow,
  UniqueConstraintViolation, OptimisticLockError,
  ItemDeleted, ItemNotDeleted,
  ConcurrentModification, UpdateAppliedButUnreadable, DeleteAppliedButUnreadable,
  CompositeKeyHoleError, CompositeNullableError,
  RefNotFound, AggregateAssemblyError,
  AggregateDecompositionError, AggregateTransactionOverflow,
  CascadePartialFailure, VersionConflict, AppendTooLarge,
  AdditionalItemConditionFailed, DuplicateCommand, StreamSealed,
  CompressorNotRegistered,
} from "effect-dynamodb"
```

| Error | Tag | Description |
|-------|-----|-------------|
| `DynamoError` | `"DynamoError"` | AWS SDK error wrapper (includes `operation` and `cause`) |
| `ThrottlingError` | `"ThrottlingError"` | AWS SDK throttling — request rate exceeded |
| `DynamoValidationError` | `"DynamoValidationError"` | DynamoDB rejected the request as malformed |
| `InternalServerError` | `"InternalServerError"` | Transient DynamoDB failure |
| `ResourceNotFoundError` | `"ResourceNotFoundError"` | Table or index does not exist |
| `ItemNotFound` | `"ItemNotFound"` | No item under the key: `get`, an `update` of a missing item (unless it is a plain `.set()` of a complete item), `restore` with no soft-deleted item or after a concurrent restore won |
| `ConditionalCheckFailed` | `"ConditionalCheckFailed"` | A `.condition()` was not met (put, update, delete, create), or an op's own guard was: `create()` of an existing item or aggregate, `patch()` or `deleteIfExists()` of a missing item, whatever `.condition()` was added. A lost version race is an `OptimisticLockError` instead |
| `ValidationError` | `"ValidationError"` | Schema decode/encode failed, or the operation was refused: an item of a versioned entity with an incarnation token but no version, a write that would overwrite a different `v#N` snapshot, a replacing put in `Batch.write`, a write DynamoDB rejected for touching one item twice, passing 4 MB, holding an item over 400 KB, a partition key over 2048 bytes, a sort key over 1024 bytes or an empty key value, a condition over DynamoDB's expression limits, or an `isIn` with no values (diagnosed from DynamoDB's rejection, naming the item, with DynamoDB's error as the `cause`), an `eventMetadata` or `eventTimestamps` whose length differs from the events (or an `eventTimestamps` entry that is not a `DateTime`), a malformed `headProof`, one naming no additional item or an item without a condition of its own, a `"snapshot"` proof without `snapshot`, a `loadState` result that is not an `Option` of a non-negative integer version, a condition or filter with an empty part under `or()` / `not()` (or an `or()` with no parts), `.consistentRead()` on a GSI (an aggregate's assembly read included) or a query's key bound DynamoDB rejected (an empty bound, a reversed `between`; diagnosed, naming the index), a vector search's `topK` outside 1–100 (diagnosed), `.expectedVersion()` on an entity that isn't `versioned`, or a stream index read whose rows lack attributes the index's declared `projection` holds (`operation: "EventStore.index.decode"`, naming the index: the deployed index likely projects less than declared; the decode error is the `cause`) |
| `ProjectionSourceConflict` | `"ProjectionSourceConflict"` | A multi-source projection's row keeps `source`'s checkpoint in a field owned by stream instance `recorded`, `arriving` addressed the row, and the projection declares no checkpoint map to hold a second instance. Nothing was written |
| `StreamRecordIdentifierMissing` | `"StreamRecordIdentifierMissing"` | A change-feed record to report in a partial batch response has no identifier (`index` among the failed records, `member` read): `EventStore.batchResponse` / `processBatch`. Fail the invocation so the source redelivers the batch |
| `DeleteAppliedButUnreadable` | `"DeleteAppliedButUnreadable"` | A delete with `returnValues("allOld")` was applied, but the item it removed (`item`, as stored) could not be decoded. Don't retry it |
| `TransactionCancelled` | `"TransactionCancelled"` | Transaction rejected (includes cancellation `reasons`) |
| `TransactionOverflow` | `"TransactionOverflow"` | DynamoDB rejected a write's own transaction (the item, its sentinels and snapshot) for exceeding its 100-item limit; nothing was written. `cause` holds DynamoDB's error |
| `AppendTooLarge` | `"AppendTooLarge"` | DynamoDB rejected an `EventStore.append` for exceeding the 100-item transaction limit; nothing was written (`streamName`, `streamId`, `count` — the items sent, `limit`; `cause` holds DynamoDB's error). Never split: run a large command as stepped commands, and read `count` against `limit` as the step size being too large |
| `UniqueConstraintViolation` | `"UniqueConstraintViolation"` | Unique constraint violated on put/create/upsert/update, or by a put in `transactWrite` / `append`'s `additionalItems` |
| `OptimisticLockError` | `"OptimisticLockError"` | A versioned write lost a version race: `expectedVersion()` did not match, or another writer changed the item between the read and the write of a read-then-write update, or a `put`, `upsert` or transaction put lost that race on every attempt. `actualVersion` is the stored version (`entityType`, `key`, `expectedVersion`, `actualVersion`) |
| `ConcurrentModification` | `"ConcurrentModification"` | An unversioned write that reads first (a unique-field change, a computed change to an index composite, a `put` or `upsert` of a unique-constrained entity — the last two after every attempt) found that another writer changed one of the attributes it read before its write landed, or a unique sentinel it was releasing changed hands. Nothing was written; retrying recomputes from the new values (`entityType`, `key`, `attributes`, `current`) |
| `UpdateAppliedButUnreadable` | `"UpdateAppliedButUnreadable"` | A retain update WAS applied at `version`, but another write replaced the item before it could be read back, and no snapshot proves what this update wrote. Don't retry a non-idempotent update on this error; read the item instead (`entityType`, `key`, `version`, `reason`) |
| `ItemDeleted` | `"ItemDeleted"` | Item is soft-deleted (get returns this instead of the item) |
| `ItemNotDeleted` | `"ItemNotDeleted"` | `restore` found a live item under the key as well as the soft-deleted one (for example, the item was recreated after it was deleted) |
| `CompositeKeyHoleError` | `"CompositeKeyHoleError"` | EDD-9024 — **deprecated in v1.7.1**, no longer thrown at runtime. Class export retained for back-compat with consumers who type-imported it for `Effect.catchTag` handlers. Hole patterns now collapse into the unified per-half can't-compose rule (drop under sparse, noop-or-cascade-override under preserve). |
| `CompositeNullableError` | `"CompositeNullableError"` | EDD-9025 — composite attribute Schema includes `null`. Raised at `Entity.make()` time. Carries `entityType`, `surface` (e.g. `"primaryKey"`, `"index:..."`, `"unique:..."`), `compositeAttribute`, `schemaPath`. |
| `RefNotFound` | `"RefNotFound"` | Referenced entity not found during ref hydration (`entity`, `field`, `refEntity`, `refId`) |
| `AggregateAssemblyError` | `"AggregateAssemblyError"` | Aggregate read path failed — missing items, structural violations, or decode errors (`aggregate`, `reason`, `key`) |
| `AggregateDecompositionError` | `"AggregateDecompositionError"` | Aggregate write path failed — schema validation or structural error (`aggregate`, `member`, `reason`) |
| `AggregateTransactionOverflow` | `"AggregateTransactionOverflow"` | Sub-aggregate exceeds 100-item transaction limit (`aggregate`, `subgraph`, `itemCount`, `limit`, `committed`). Not checked before sending: DynamoDB rejects the group, nothing from it is written, and DynamoDB's error is the `cause`. Each group is its own transaction, so `committed` names the sub-aggregates earlier groups of the same write already committed, and the `message` says so; for a failed `create` (`operation: "create"`), it adds that the root may be committed, so a retried create fails its root guard: update or delete the partial aggregate |
| `CascadePartialFailure` | `"CascadePartialFailure"` | Cascade update partially failed in eventual mode (`sourceEntity`, `sourceId`, `succeeded`, `failed`, `errors`) |
| `VersionConflict` | `"VersionConflict"` | Event store version mismatch: an append's version guard failed (the contiguity check, an event put, or a `headProof` item's own condition), or a command handler call's `expectedVersion` did not match the loaded version (`streamName`, `streamId`, `expectedVersion`, `actualVersion?` — set by the pre-decide If-Match check and when a `verifySnapshot: false` If-Match decision is checked against the head, unset on any other append-time conflict). `streamName` / `streamId` name the stream whose check failed: a nested `appendOp`'s failure names that op's stream, not the appending one |
| `AdditionalItemConditionFailed` | `"AdditionalItemConditionFailed"` | A condition the caller set on an `EventStore.append({ additionalItems })` op (`.condition()`, `create()`, `Transaction.check`) failed — NOT a version conflict, and never an op the caller set no condition on (`streamName`, `streamId`, `indices`, `reasons`) |
| `DuplicateCommand` | `"DuplicateCommand"` | A `commandId` was already applied to this stream (`streamName`, `streamId`, `commandId`) |
| `StreamSealed` | `"StreamSealed"` | An append's stream is sealed (`streamName`, `streamId`, `sealedVersion`: the sealing event's version, the stream's final one): an append, a nested `appendOp`, or a command handler whose load found the seal. Terminal, never retried. Precedence is per stream: within one stream's items it ranks after `DuplicateCommand` and ahead of that stream's `VersionConflict`; across streams the appending stream's own verdict comes first, then nested `appendOp`s in op order (the first failing op wins), then the other additional items |
| `CompressorNotRegistered` | `"CompressorNotRegistered"` | Never in an error channel — the `cause` of the `ValidationError` a [packed](/effect-dynamodb/guides/packed-storage/) value fails with when it needs a compression codec that is not registered: writing a value over its threshold, or reading a `B` value whose header names the codec (`codec`, `direction: "compress" \| "decompress"`, `entityType`, `attribute`, `operation`) |

### Errors by operation

Each operation declares a fixed error union, whatever the entity's configuration. Every union also includes `DynamoClientError`, plus ref and vector errors where the entity has refs or vector indexes. `.condition()` adds `ConditionalCheckFailed` to an operation that lacks it.

| Operation | Declared errors (besides `DynamoClientError`) |
|-----------|-----------------------------------------------|
| `put` | `ValidationError`, `UniqueConstraintViolation`, `OptimisticLockError`, `ConcurrentModification`, `TransactionOverflow` |
| `create` | as `put`, plus `ConditionalCheckFailed` |
| `upsert` | as `put`, plus `ItemNotFound`, `ConditionalCheckFailed` |
| `update` | `ItemNotFound`, `OptimisticLockError`, `ConcurrentModification`, `UpdateAppliedButUnreadable`, `UniqueConstraintViolation`, `ValidationError`, `TransactionOverflow` |
| `patch` | as `update`, plus `ConditionalCheckFailed` |
| `delete` | `ItemNotFound`, `OptimisticLockError`, `ConcurrentModification`, `ValidationError`, `TransactionOverflow`, `DeleteAppliedButUnreadable` |
| `deleteIfExists` | as `delete`, plus `ConditionalCheckFailed` |
| `restore` | `ItemNotFound`, `ItemNotDeleted`, `ValidationError`, `UniqueConstraintViolation`, `TransactionOverflow` |
| `purge` | `ValidationError` |
| `Transaction.transactWrite` | `ValidationError`, `TransactionCancelled`, `UniqueConstraintViolation`, `OptimisticLockError`, `ConcurrentModification` |
| Aggregate `create` | `AggregateWriteError` plus `ConditionalCheckFailed` |
| `EventStore` `append` / `commandHandler` (plus the decider's errors) | `VersionConflict`, `StreamSealed`, `DuplicateCommand`, `AdditionalItemConditionFailed`, `AppendTooLarge`, `ValidationError`, `TransactionCancelled`, `UniqueConstraintViolation`, `OptimisticLockError`, `ConcurrentModification` |

### Usage

```typescript
const db = yield* DynamoClient.make({
  entities: { UserEntity },
  tables: { MainTable },
})
const users = db.entities.UserEntity

const user = yield* users.get({ userId: "u-1" }).pipe(
  Effect.catchTag("ItemNotFound", () => Effect.succeed(null)),
  Effect.catchTag("DynamoError", (e) =>
    Effect.die(`DynamoDB ${e.operation} failed: ${e.cause}`)
  ),
)
```
